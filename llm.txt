# mcp-framework

> Rust framework for building MCP (Model Context Protocol) servers. Wraps `rmcp` 3.1 to handle
> transport, auth, sessions, capabilities, audit and CLI so you only implement `rmcp::ServerHandler`.

## Dependency

```toml
[dependencies]
mcp-framework = { git = "https://github.com/Plawn/mcp-framework" }
rmcp = { version = "3.1", features = ["server"] }
tokio = { version = "1", features = ["full"] }
anyhow = "1"
```

Requires Rust **nightly** (edition 2024). Optional cargo features: `redis` (Redis persistence
backend), `metrics` (effectiveness metrics + `/metrics` endpoint).

`mcp_framework::prelude::*` re-exports everything below, plus the rmcp types a consumer needs
(`ServerHandler`, `RequestContext`, `RoleServer`, `Tool`, `CallToolResult`, `ContentBlock`,
`Parameters`, `schemars`, `McpError`, …) so `rmcp` is not needed as a direct dependency for them.

## Minimal example

```rust
use mcp_framework::prelude::*;

struct MyServer;

// Implement rmcp::ServerHandler — see rmcp docs for #[tool] / #[prompt] / #[resource] macros.
impl ServerHandler for MyServer {}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    McpAppBuilder::new("my-server")
        .server(|| MyServer)
        .run()
        .await
}
```

The server factory takes **no arguments**: `Fn() -> impl ServerHandler`. Tokens and sessions are
reached from the request context via `RequestContextExt` (see below), not passed to the factory.

## McpAppBuilder

```rust
McpAppBuilder::new("my-server")            // -> McpAppBuilder<(), ()>
    .with_sessions::<MySession>()          // typed per-session data (changes T)
    .auth(AuthProvider::OAuth(OAuthConfig::from_env()?))
    .settings(Settings { ..Default::default() })   // bypasses CLI + .env
    .stdio_token_env("MY_APP_TOKEN")       // env var holding the bearer in stdio mode
    .capability_registry(registry)         // dynamic tools/prompts/resources
    .capability_filter(Arc::new(ToolFilter(|tools, token| tools)))   // visibility
    .access_validator(Arc::new(ToolCallValidator(|name, args, token, session| AccessDecision::Allow)))
    .claims_decoder(decode_jwt)            // global, typed JWT claims
    .tool_call_logger(Arc::new(TracingLogger))
    .metrics(collector)                    // feature "metrics"
    .persistence(Arc::new(RedisBackend::connect("redis://127.0.0.1/").await?))
    .protocol_lifecycle(ProtocolLifecyclePolicy::Hybrid)
    .extra_routes(router)                  // axum routes BEHIND the auth layer
    .public_routes(router)                 // axum routes OUTSIDE the auth layer (health, probes)
    .loopback()                            // in-process client factory — call LAST, &mut self
    .run().await                           // or .build()? -> McpApp
```

`build()` / `run()` fail on: an unparseable `bind_addr`, a `session_ttl` under 1 s, an OAuth config
with an empty `client_id` / `issuer_url` / `redirect_url`, `TokenMode::ResourceServer` without
`OAUTH_EXPECTED_AUDIENCE`, or any field configured *after* `loopback()` handed out an endpoint.

## McpApp (struct API)

```rust
pub struct McpApp<F, T = ()> where T: SessionData {
    pub name: String,
    pub auth: AuthProvider,
    pub server_factory: F,                       // Fn() -> impl ServerHandler
    pub stdio_token_env: Option<String>,
    pub settings: Option<Settings>,              // None = CLI args + env vars + .env
    pub capability_registry: Option<CapabilityRegistry>,
    pub capability_filter: Option<Arc<dyn CapabilityFilter>>,
    pub access_validator: Option<Arc<dyn AccessValidator>>,
    pub claims_decoder: Option<ClaimsDecoderFn>,
    pub session_store: Option<SessionStore<T>>,
    pub tool_call_logger: Option<Arc<dyn ToolCallLogger>>,
    pub persistence: Option<Arc<dyn PersistenceBackend>>,
    pub protocol_lifecycle: ProtocolLifecyclePolicy,
    pub extra_routes: Option<Router>,
    pub public_routes: Option<Router>,
}

mcp_framework::run(app).await
```

## Settings (programmatic config)

When `settings` is `Some(..)`, no CLI parsing happens and `.env` is not loaded.

```rust
Settings {
    transport: TransportMode::Http,     // Http | Stdio  (there is no SSE transport)
    log_level: LogLevel::Info,          // Error | Info | Debug | Trace
    bind_addr: "0.0.0.0:4000".into(),
    public_url: None,                   // None derives http://{bind_addr}
    session_ttl: None,                  // None = 30 minutes
}
```

CLI mode (`settings: None`) parses `--transport http|stdio`, `--debug`, `--trace` and reads the
environment variables listed at the end.

## Transports

- **Http** — Streamable HTTP, MCP endpoint at `/mcp`.
- **Stdio** — stdin/stdout, for local Claude Desktop integration.

`ProtocolLifecyclePolicy::Hybrid` (default) negotiates a client that advertises a sessionless
version (2026-07-28+) but uses the legacy `initialize` lifecycle down to `2025-11-25`, so rmcp
creates a session for it. `Strict` applies rmcp's routing unmodified. Correct modern clients using
`server/discover` are always served statelessly.

## Authentication

```rust
auth: AuthProvider::None,
auth: AuthProvider::Basic(BasicAuthConfig { username, password }),   // or ::from_env()?
auth: AuthProvider::OAuth(OAuthConfig { .. }),                       // or ::from_env()?
```

```rust
pub struct OAuthConfig {
    pub client_id: String,
    pub client_secret: Option<String>,
    pub issuer_url: String,      // Keycloak realm URL
    pub redirect_url: String,
    pub scopes: Vec<String>,
    pub token_mode: TokenMode,                                 // Passthrough | Opaque | ResourceServer
    pub unknown_token_validation: UnknownTokenValidation,      // Jwks | Introspection | JwksThenIntrospection | Reject
    pub expected_audiences: Vec<String>,                       // empty = `aud` unconstrained
}
```

### Token modes

| Mode | Client holds | Server keeps | Refreshes | Scaling |
|---|---|---|---|---|
| `Passthrough` (default) | the Keycloak JWT | access + refresh token | both sides | needs shared persistence |
| `Opaque` | a framework UUID | access + refresh token | the framework | needs shared persistence |
| `ResourceServer` | the Keycloak JWT | nothing | the client, alone | stateless |

`ResourceServer` is what MCP 2025-06-18 and later specify. It validates the inbound JWT against the
issuer's JWKS and keeps no token state; `OAUTH_EXPECTED_AUDIENCE` is **mandatory** (boot fails
without it), `OAUTH_UNKNOWN_TOKEN_VALIDATION=introspection|reject` are boot errors and the default
is coerced to `jwks`. `/oauth/token`, `/oauth/authorize`, `/oauth/login`, `/oauth/callback` and
`/oauth/status` answer `404`; `/oauth/register` stays (Keycloak's own registration endpoint sends
no CORS headers). Discovery points clients at Keycloak.

A bearer the proxy did not issue goes through `TokenStore::validate_unknown_bearer`: store → JWKS →
introspection, ordered by `unknown_token_validation`. A JWKS *rejection* is final (never re-litigated
through introspection); only "could not answer" falls through.

## Accessing tokens and sessions — `RequestContextExt`

Available on `RequestContext<RoleServer>` inside any handler:

```rust
let id      = context.session_id();               // &str, "default" in stdio mode
let session = context.session::<MySession>();     // Session<'_, T>; panics without .with_sessions::<T>()
let token   = context.token().await;              // Option<StoredToken> — PREFER THIS
let store   = context.token_store();              // &TokenStore
```

Use `ctx.token()` rather than `ctx.token_store().get_token(ctx.session_id())`: in
`TokenMode::ResourceServer` there is no store entry, and the credential is attached to the request
instead. `StoredToken { access_token, refresh_token, expires_at }` plus `token.claims::<C>()` for
the globally decoded claims; `refresh_token` is always `None` in resource-server mode.

## SessionStore

`SessionStore<T>` — typed per-session data with TTL (default 30 min) and background cleanup in HTTP
mode. `T: Send + Sync + Default + Clone + Serialize + DeserializeOwned + 'static` (`SessionData`).

```rust
// Session<'_, T> handle, from the request context:
session.id();                                  // &str
session.get().await;                           // Option<T>
session.get_or_create().await;                 // T
session.update(|s| s.count += 1).await;        // T
session.remove().await;                        // Option<T>

// SessionStore<T> directly (same methods, taking session_id: &str):
store.get / get_or_create / update / remove / purge_expired / load_persisted / len / ttl
```

`resolve_session_id(&extensions) -> &str` and `session_id_from_parts(&Parts) -> &str` resolve the
identity: the framework header first, then `mcp-session-id`, then `"default"`. On sessionless
protocol revisions the identity is derived from the credential's claims (`sid`, else `sub`).

## Capabilities

```rust
let registry = CapabilityRegistry::default();
registry.add_tool(tool, |args| async { Ok(CallToolResult::success(vec![ContentBlock::text("ok")])) }).await;
registry.add_tool_with_context(tool, |args, ctx| async { .. }).await;   // ToolCallContext
registry.add_prompt(prompt, handler).await;
registry.add_resource(resource, handler).await;
registry.remove_tool("name").await;            // also remove_prompt / remove_resource
registry.tools().await;                        // also prompts() / resources()

// MCP Apps (ext-apps): a tool with a companion HTML UI
registry.register_app_resource("ui://my-server/chart", include_str!("chart.html")).await;
let tool = CapabilityRegistry::app_tool(tool, "ui://my-server/chart");
```

- **`CapabilityFilter`** controls *visibility* (`ToolFilter` / `PromptFilter` / `ResourceFilter`
  wrap a closure for one type and pass the others through).
- **`AccessValidator`** controls *execution* — `validate_tool_call` / `validate_prompt_access` /
  `validate_resource_access` returning `AccessDecision::Allow | Deny(reason)`; `ToolCallValidator`
  wraps a closure for tool calls only. A tool hidden by a filter can still be called by name, which
  is the gap this closes.
- Tool schemas are sanitized on the way to `tools/list` (`$schema`/`title` stripping, `$defs`
  inlining, root `oneOf`/`anyOf`/`allOf` flattening, missing `"type": "object"`), and undocumented
  tools/properties are warned about once per version.

## Audit & metrics

```rust
.tool_call_logger(Arc::new(TracingLogger))     // or NoopLogger, CompositeLogger, or your own
```

`ToolCallLogger::log(&self, ToolCallRecord) -> Pin<Box<dyn Future<Output = ()> + Send>>`, called
fire-and-forget for every `call_tool`. `ToolCallRecord { tool_name, arguments, session_id,
timestamp, duration, source, outcome }`; `ToolCallOutcome::Success { is_error, content_summary }`
or `McpError { code, message }`; `ToolCallSource::Registry | Inner`.

With the `metrics` feature, `MetricsCollector` *is* a `ToolCallLogger`: `.metrics(collector)` logs
records and mounts a Prometheus endpoint (default `/metrics`, `?format=json`) outside the auth
layer; `collector.snapshot()` works in-process, stdio included.

## Persistence

```rust
.persistence(Arc::new(RedisBackend::connect("redis://127.0.0.1/").await?))  // feature "redis"
.persistence(Arc::new(InMemoryBackend::new()))                              // testing
```

`PersistenceBackend` — async namespaced key-value (`get`/`set`/`delete`/`keys`/`touch`, plus
`try_acquire_lock`/`release_lock` for the distributed refresh lock). Write-through on mutation,
load at startup, read-through on a memory miss — which is what makes multi-instance deployment work
without sticky sessions. Wired into the token store, the session store, the capability registry and
rmcp's transport sessions. No backend = no serialization and no overhead.

## In-process clients (loopback)

```rust
let loopback = builder.loopback();   // take it LAST; does not consume the builder
let session = loopback.connect(LoopbackIdentity::new("thread-42")).await?;
let tools = session.list_all_tools().await?;
```

An in-process caller becomes a real MCP client over channels, so it goes through the same handler,
registry, capability filter, access validator and tool-call logger as network traffic (calling
`CapabilityRegistry::call_tool` directly bypasses all four). The endpoint keeps its own `TokenStore`
and `SessionStore`, so in-process session data is not persisted. `Arc<dyn DynLoopback>` is the
object-safe form. Errors: `InvalidIdentity`, `UnresolvableCredential` (a bearer under
`TokenMode::Opaque`), `Initialize`.

## HTTP endpoints

- `/mcp` — the MCP protocol endpoint (Streamable HTTP).
- With OAuth: `/.well-known/oauth-protected-resource` (+ `/mcp` suffix),
  `/.well-known/oauth-authorization-server`, `/oauth/register`, `/oauth/authorize`, `/oauth/token`,
  `/oauth/login`, `/oauth/callback`, `/oauth/status`.
- `/metrics` with the `metrics` feature, plus anything passed to `public_routes` — outside auth.
